# Web 管理后台

此分支在原 Bot 进程内运行可选的中文 Web 后台，继续共用原数据库与抓取、发送流程。
这是单实例的**超级管理员**后台，登录密钥持有者可以查看、编辑此 Bot 的全部用户、频道和群聊订阅。
它管理的是当前部署的这一只 Bot；不连接别人的 Bot，也不是多个 Bot Token 的集中控制平台。

## 启动

保留原来的 TOKEN、MANAGER 等部署设置，在 `.env` 中新增：

```dotenv
WEB_ADMIN_TOKEN=请换成至少32个字符的随机密钥
WEB_ADMIN_HOST=127.0.0.1
WEB_ADMIN_PORT=8080
```

生成密钥：`python -c 'import secrets; print(secrets.token_urlsafe(32))'`。
按原项目方式运行 `python telegramRSSbot.py`，打开 `http://127.0.0.1:8080` 并输入密钥。
未设置 WEB_ADMIN_TOKEN 时，后台完全不监听端口；无效的短密钥会拒绝启动。
密钥仅保存在当前页面内存中，刷新页面需要重新登录。

Docker 用户请复制 `docker-compose.web.yml.sample` 为 `docker-compose.web.yml`，准备好 `.env`，运行：

```console
docker compose -f docker-compose.web.yml up -d --build
```

必须构建此分支，上游发布的镜像不包含这些功能。容器内监听 0.0.0.0，但示例只将端口映射到宿主机回环地址。
远程使用可通过 SSH 转发端口：`ssh -L 8080:127.0.0.1:8080 用户名@服务器`。
若通过反向代理公开后台，配置 HTTPS 并保持页面与 API 同源。

## 订阅与接收目标

- 后台读取数据库内的所有私聊、频道和群聊订阅，可搜索、按目标筛选、添加、删除、暂停、启用和编辑。
- 可编辑订阅标题、标签、检查间隔、消息格式和关键词规则；RSS 地址与接收目标为订阅身份，变更时重新添加对应订阅再删除旧订阅。
- 私聊用户须先在 Telegram 向 Bot 发送 `/start`。频道或群聊须先加入 Bot，并给予发消息所需权限，再在后台用 `@用户名` 或聊天 ID 添加接收目标。
- “接收目标”页编辑消息格式的默认值，订阅可以继承或覆盖这些默认值。
- “全局配置”页编辑默认/最小检查间隔、订阅上限和上限提示。部署级设置如 Bot Token、代理等继续由环境变量配置。

## 关键词过滤

规则按每一条**订阅**保存，同源发往不同目标可以有不同规则。

- 每行一个字面关键词，不使用正则表达式。
- “必须包含”支持任意一个或全部匹配；留空时不限制。
- 任意“排除”关键词匹配即不发送，优先于包含条件。
- 可选仅标题或标题与正文；去除 HTML 标记，统一全角/半角和字母大小写。
- 每组最多 100 个关键词，每词最多 200 字符。
- 规则仅作用于之后抓取的新文章。被过滤文章也会记入抓取历史，修改规则不会补发历史文章。
- 抓取失败、源停用等运维通知不会被关键词过滤。

升级时自动应用 SQLite / PostgreSQL 的新增字段迁移。首次运行前建议复制原数据库备份。
旧版本程序不认识新字段，不建议直接回滚代码。

## ZIP 备份与还原

备份包含全部聊天目标及默认值、RSS 源、文章去重历史、订阅全部消息设置、关键词规则和数据库全局选项。
可勾选包含运行配置，加入 Bot Token、管理员、API 凭据、Telegraph Token、代理与常用网络设置。
导出文件含私人信息，包含运行配置时还含密钥，应作为敏感文件保管。

还原流程：上传 ZIP → 格式和关联校验 → 预览记录数量 → 确认合并。
还原通过聊天 ID、RSS URL 和两者的订阅关系匹配，重新映射数据库内部 ID，不要求新旧 ID 相同。

- 备份内的目标默认值、对应订阅设置和全局选项覆盖当前值，当前额外订阅保留。
- 当前已有 RSS 源保留现有抓取历史；新建的 RSS 源继承备份历史，避免重发旧文章。
- 数据库写入在事务中完成；导入过程写入失败则回滚。
- 执行前自动将当前状态保存到 `config/web-backups/时间戳.zip`，文件权限 0600；需要时可重新上传作合并还原。
  自动备份是合并恢复点，不会自动删除后来新增的订阅。
- 勾选还原运行配置时，写入 `config/web-restored.env`（0600），**重启 Bot 后生效**。
  此文件优先于原 `.env` 与进程环境中的对应键；希望回到原部署配置时先移走该文件再重启。
- 不覆盖 `DATABASE_URL`、Web 登录密钥、Web 监听地址/端口，不包含 Telegram 会话文件。
  在全新机器上需先配置 Bot Token、管理员、数据库连接和 Web 密钥，启动后导入；Bot 会重新登录 Telegram。
- 最大上传及解压后 JSON 大小为 16 MB，仅接受此后台的 v1 ZIP 格式，不解压任何上传路径。

## 验证

```console
PYTHONPATH=. python tests/test_admin.py
python tests/test_migrations.py
```

测试使用临时 SQLite 和本机 HTTP 服务，不连接 Telegram。覆盖登录、来源校验、订阅增删改、独立规则、
Unicode/HTML 匹配、备份预览、ID 重映射、失败事务回滚以及敏感配置还原。
生产前仍需使用自己的 Bot 测试私聊、频道与群聊权限和实际发送；PostgreSQL 迁移需在对应环境验证。

本项目沿用上游 AGPLv3+。发布自己的 fork 后，请把 `src/i18n/__init__.py` 中的 REPO_URL 改成自己的公开源码地址，
让使用者可以取得实际运行版本的源码。
